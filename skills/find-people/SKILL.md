---
name: find-people
description: Find people or companies that match criteria with Data Legion Discover or search. Use when the user wants a prospect or target list, for example "engineers at fintech companies in Austin" or "software companies with more than 200 employees".
---

To build a list:

1. If the request is in plain words, try `person_discover` or `company_discover` first with the request exactly as the user wrote it, a `limit` (start with 10: it returns one record unless asked for more) and `include_fields`: Data Legion writes the search and returns it as `generated_query`. Then show the results as in steps 6 and 7. If it refuses a part it cannot filter on (a school, funding, contact details), tell the user and offer the search for the rest that the error names. If a 403 says this key is limited to other endpoints, it lists what the key can call: use only those, or tell the user. For the next page, pass the previous page's `next_cursor` back as `cursor` with the same query and no `offset`: it reruns the same search.
2. Otherwise search with `filters` on `person_search` or `company_search`. Its keys are the record's own field names, the ones every result carries: for people `job_title`, `seniority_level`, `company_name`, `company_domain`, `company_industry`, `city`, `state_code`; for companies `industry`, `size`, `type`, `linkedin_employee_count`, `locations.city`, `locations.country_code`. A value or a list (any of them), `{"gte": .., "lte": ..}` for a number, `{"exists": true}`; every field given must hold. Group with `{"and": [...]}`, `{"or": [...]}` or `{"not": {...}}`, and use `keywords` for a Boolean search of the profile text (`AND`, `OR`, `NOT` in capitals, "quoted phrases"). Example: `{"job_title": ["vp of sales", "head of sales"], "state_code": "TX"}`. The headquarters is `{"locations.city": "austin", "locations.primary": true}`.
3. For what filters can't say, send `sql` (`SELECT * FROM people WHERE ...` or `SELECT * FROM companies WHERE ...`) or `es_query` (a query object on the response's field names). Send exactly one of `filters`, `sql` or `es_query`.
4. Before a big list, `person_count` or `company_count` with the same input says how many match, rounded and free (even with no credits left), so you can tell the user what it would cost (one credit per record) before you run it.
5. Don't put LIMIT or OFFSET in the SQL. Use the `limit` and `offset` parameters: start with `limit: 10` to check the results look right, then page with `offset`. To go past 10,000 results or export a whole list, pass each page's `next_cursor` back as `cursor` instead of `offset`; on the last page it is null.
6. Trim results with `include_fields` so a page of results stays readable.
7. Show results as a table and say how to get the next page. If a promising person is missing contact details, offer to run `person_enrich` on them.
